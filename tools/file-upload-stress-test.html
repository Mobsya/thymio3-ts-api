2. Configure the barrage

Uploads run one at a time, as fast as the robot acknowledges them. Generated files stay in RAM; this test does not save or erase files in storage.

Each preset uses 10 × 43,000-byte uploads, RAM cleanup, a 30-second upload inactivity timeout, and stops on the first upload failure. Enabled background traffic starts after the first packet. For comparable runs, restart the robot and reload this page between scenarios, then connect and select a preset. No console commands are needed. The upload timer restarts after each completed packet, so a large file can take longer than this. Setup and RAM cleanup use this value as their operation deadline. The defaults cover small files, packet boundaries at the 500-byte write limit, and larger transfers. Sizes may range from 0 to 1,048,576 bytes. Before uploads waits for data from each selected sensor stream. After first packet starts streaming once during the first upload, then starts memory polling as soon as the streaming command completes, matching the reported reproduction. Background traffic stays active across uploads until the run ends. Each memory read waits for a response or its timeout, then waits the configured delay before the next read. Like the reproduction script, polling continues after errors and timeouts; a timed-out API request may still be pending. The initial firmware/memory snapshot is separate from polling. Any requests still pending at shutdown require disconnection and a page reload.

Keeping the same sizes and seed reproduces the generated bytes. Disconnections and unconfirmed transfers always stop the run. A stalled operation requires a page reload.
